People search for "IBM Bob vs Claude Code" and similar comparisons, and most of the pages that answer are feature-list templates. This page is different in one way and limited in another. Tejas Kumar and David Jones-Gilardi have built two open-source apps, [KillrCtx](/projects/killrctx) and [Walfly](/projects/walfly), with IBM Bob across ten livestreams, so everything we say about Bob is backed by a timestamp. We have not run the same task in Claude Code, Cursor or Codex, so everything we say about those tools comes from their own documentation, re-checked in late September 2026 and linked inline, plus a few asides from hosts who use them daily. Both hosts work at IBM. There is no winner here; these are notes to help you decide what to try.

## How they differ in approach

All four are agentic coding tools that read a repository, plan, edit files and run commands, and the differences are mostly in defaults and packaging. The hosts frame Bob the same way: "Bob is IBM's coding agent. You may think of things like Codex, Claude Code, Cursor… Bob is that" ([0:00](/episodes/killrctx-open-source-notebooklm-clone-with-openrag-and-ibm-bob?t=0)). Tejas describes Bob Shell as the command-line counterpart to Claude Code and the Bob IDE as "the VS Code fork" ([20:02](/episodes/killrctx-open-source-notebooklm-clone-with-openrag-and-ibm-bob?t=1202)); and when the hosts went looking for Live Share, the verdict was "this is very clearly VS Code" ([30:39](/episodes/notebooklm-clone-setup-wizard-and-ai-workbench-backend?t=1839)).

## Model choice

The biggest practical difference we noticed is that Bob chooses the model and the others let you choose. IBM's launch announcement says Bob "dynamically routes tasks to a suitable model based on accuracy, performance, and cost," drawing on Anthropic Claude, Mistral open-source models and IBM Granite. Asked which model Bob uses, David answered in July 2026 that it's a combination, sometimes Granite, with "some Anthropic in there," and "it's not something that it exposes to you" ([35:45](/episodes/notebooklm-clone-setup-wizard-and-ai-workbench-backend?t=2145)).

That came up again in [Bob Review vs Xavier and a KeyboardAvoidingView Fix in Expo](/episodes/ai-code-review-and-expo-mobile-layout-fixes), when David asked whether any tools were tuned for mobile ([52:52](/episodes/ai-code-review-and-expo-mobile-layout-fixes?t=3172)):

> There's an AI model. And I guess this is where Bob falls short, because it doesn't let you choose the model. But there's a model called Apex that is purpose-built, purpose-trained for mobile app development.
> — Tejas [53:22](/episodes/ai-code-review-and-expo-mobile-layout-fixes?t=3202)

Claude Code (`/model`), Codex (`/model`) and Cursor (a model picker) all document manual selection. Cursor's Auto mode also routes for you, and its docs say that with Cursor Router "you can't hand-pick which model handles a request." So automatic routing isn't unique to Bob; the difference is that Bob, in our setup, had no manual option. [IBM's FAQ](https://bob.ibm.com/docs/ide/faq) lists "Can I choose which model Bob uses?", but we couldn't read the answer when we fetched it, so treat this as unconfirmed for other plans.

## Permissions and safety defaults

Bob starts cautious and makes you opt in to autonomy. In [IBM Bob Plan Mode: Scoping a Real App MVP, Live](/episodes/planning-walfly-wearable-app-mvp-with-ibm-bob), David described this as deliberate:

> Bob is optimized for enterprise applications and building fully fledged applications, but their security model starts, instead of just being super permissive, the exact opposite way.
> — David [55:59](/episodes/planning-walfly-wearable-app-mvp-with-ibm-bob?t=3359)

You can open it up in steps. IBM's auto-approve page offers per-category toggles (read, edit, execute, MCP, skill, subagent and more) and task-level overrides; on stream, David approved `gh` commands "for the task" while keeping others gated ([56:16](/episodes/notebooklm-clone-setup-wizard-and-ai-workbench-backend?t=3376)). Bob still asked before reading the files of [Xavier](https://xavier.team), an AI agent orchestrator by Atila, in David's home folder outside the workspace ([35:30](/episodes/ai-code-review-and-expo-mobile-layout-fixes?t=2130)). At the far end, Tejas runs Bob Shell in YOLO mode, toggled in July 2026 with Shift+Tab, and says "I really don't like when AI agents ask me for permission" ([11:46](/episodes/debugging-rag-backends-openrag-vs-ai-workbench?t=706)). IBM's [Bob Shell auto-approve docs](https://bob.ibm.com/docs/shell/features/auto-approving-actions) describe a settings file and a `/permissions` command rather than a "YOLO" name, so check the current control.

For the others, the documented defaults vary. Claude Code says that from v2.1.283, auto mode, where a classifier reviews actions instead of you, is the starting mode for interactive terminal and VS Code sessions. Cursor calls its Auto-review run mode "the safest useful setup for most people." Codex runs locally in a sandbox with no network access and writes limited to the workspace. None of these is simply "safer": they put the check in different places.

## Planning and spec workflow

All four document a plan mode; with Bob we saw how it behaves on real projects, and how far a custom spec-coding mode goes beyond it. In the first Walfly episode, plan mode asked questions first ([27:45](/episodes/planning-walfly-wearable-app-mvp-with-ibm-bob?t=1665)), produced subtasks with IDs ([35:06](/episodes/planning-walfly-wearable-app-mvp-with-ibm-bob?t=2106)) and switched itself into Agent mode ([54:56](/episodes/planning-walfly-wearable-app-mvp-with-ibm-bob?t=3296)). On KillrCtx, David's spec-coding mode wrote requirements, a design and linked to-dos, and Bob offered to use it unprompted ([18:47](/episodes/adding-a-mind-map-to-a-notebooklm-clone-with-ibm-bob?t=1127)). More in [IBM Bob features in practice](/topics/ibm-bob-features-in-practice).

Two observations cut across tools:

- **Agents keep their own task lists.** David keeps to-dos in files "for posterity," and that has collided with Claude Code, which "creates its own task list" ([31:28](/episodes/adding-a-mind-map-to-a-notebooklm-clone-with-ibm-bob?t=1888)). "Bob does that as well just like Claude," so he tells it to update his file ([36:53](/episodes/adding-a-mind-map-to-a-notebooklm-clone-with-ibm-bob?t=2213)). In July 2026 he added: "Bob, Claude, a bunch of them create their own task lists internally" ([1:10:14](/episodes/notebooklm-clone-setup-wizard-and-ai-workbench-backend?t=4214)).
- **Parallel to-dos get batched.** On stream, a host recalled telling Claude Code to do 20 to-dos in parallel; it replied it would "batch them intelligently" instead ([33:42](/episodes/adding-a-mind-map-to-a-notebooklm-clone-with-ibm-bob?t=2022)). Bob, asked the same from agent mode, batched too ([34:14](/episodes/adding-a-mind-map-to-a-notebooklm-clone-with-ibm-bob?t=2054)).

The plans still had to be read carefully: Bob started Walfly on Next.js 14 and insisted Next.js 16 didn't exist ([1:03:51](/episodes/planning-walfly-wearable-app-mvp-with-ibm-bob?t=3831)).

## Code review

Bob's review is built in and closes the loop with a one-click fix, which is the feature we used most. Bob Review listed findings in the IDE, and David applied them with Fix with Bob one at a time ([37:12](/episodes/ai-code-review-and-expo-mobile-layout-fixes?t=2232), [48:51](/episodes/ai-code-review-and-expo-mobile-layout-fixes?t=2931)). It caught UX visibility issues that Xavier's review didn't flag. A later review then told the hosts to re-add the exact prop they had removed to fix a bug ([1:20:49](/episodes/ai-code-review-and-expo-mobile-layout-fixes?t=4849)), so check its findings.

Claude Code, Cursor and Codex each document a local review command and a pull-request reviewer, linked in the table. We haven't used those on our projects, so we can't compare quality.

## Memory and context across sessions

Every tool here gives you instruction files, but none solved cross-session task tracking for us on its own. When Bob got the Next.js version wrong, the hosts told it to update its memory and always search the web, and it saved that for future sessions ([1:05:11](/episodes/planning-walfly-wearable-app-mvp-with-ibm-bob?t=3911), [1:07:25](/episodes/planning-walfly-wearable-app-mvp-with-ibm-bob?t=4045)).

Task lists are another matter. David pointed out that a to-do list in Bob or Claude Code "is going to be per session" ([18:44](/episodes/local-first-transcription-python-sidecar-and-coordinating-agents?t=1124)). When Bob reached its default 100-turn limit, the hosts wished for a way to start a new session without losing context ([52:41](/episodes/local-first-transcription-python-sidecar-and-coordinating-agents?t=3161)). Switching tools makes this worse: Tejas moved from Claude Code to Codex and found "a whole bunch of context that's just not available to this new agent" ([18:39](/episodes/ai-code-review-and-expo-mobile-layout-fixes?t=1119)). The hosts keep that state outside the agent, as covered in [how to coordinate multiple coding agents](/topics/coordinating-coding-agents).

## Where each fits

Based on the docs and our own use of Bob, here is where each tool seems aimed, not a ranking:

- **IBM Bob** fits teams that want approvals on by default, model routing handled for them, and review built into the IDE. IBM's [pricing page](https://bob.ibm.com/pricing) adds enterprise controls and packages for Java modernization, IBM i and IBM Z. On stream it did well on web work and spec-driven features and needed more help with native Expo layout ([52:52](/episodes/ai-code-review-and-expo-mobile-layout-fixes?t=3172)).
- **Claude Code** fits developers who want to pick a Claude model per task and run the same agent in a terminal, IDE, desktop app or browser.
- **Cursor** fits people who want an editor-first experience with a choice of models from several providers, plus cloud agents.
- **Codex** fits developers who want OpenAI models, a sandbox by default, and the same agent across CLI, IDE and cloud.

The one direct comparison on the show comes with a disclosure. David, who uses Claude Code, GitHub Copilot and Bob, said in July 2026: "with the latest IBM Bob V2, I feel like Bob is on par with something like the experience I get out of Claude Code, especially for building apps like this" ([1:05:38](/episodes/notebooklm-clone-setup-wizard-and-ai-workbench-backend?t=3938)), then added, "Yes, I work for IBM. Yes, I'm going to have a bit of a biased opinion" ([1:06:09](/episodes/notebooklm-clone-setup-wizard-and-ai-workbench-backend?t=3969)).

The hosts don't treat the choice as permanent. Add-ons such as Beads, MCP Agent Mail and Xavier work across agents, and David's view is that agents are "not deterministic" whichever one you use ([10:28](/episodes/designing-audio-chunking-and-ephemeral-asr?t=628)).
